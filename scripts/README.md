# How the profile README is built

Every graphic in the profile README is a hand-built SVG, generated by the scripts here.
They need Node 18 or later and have no dependencies.

| File | What it does |
| --- | --- |
| `content.mjs` | All the text: profile, skills, case files, education, certifications. Edit this first. |
| `build.mjs` | Draws the static SVGs into `assets/`. Run it after editing `content.mjs`. |
| `telemetry.mjs` | Draws the live stats panel into `dist/`. The daily Action runs it. |
| `lib.mjs` | Shared palette (same tokens as janith.qzz.io), embedded fonts, and animation helpers. |
| `preview.html` | Local preview of the README, with light/dark and phone-width toggles. |
| `fonts/` | JetBrains Mono and Space Grotesk, cut down to ASCII. Both are licensed under OFL-1.1 (licence files included). |

## Workflow

```bash
node scripts/build.mjs          # redraw assets/*.svg
node scripts/telemetry.mjs      # optional: local telemetry preview in dist/
python -m http.server 8091      # then open http://127.0.0.1:8091/scripts/preview.html
```

The daily run happens in `.github/workflows/telemetry.yml`. It redraws `telemetry.svg` and the lime contribution snake, then force-pushes them to the `output` branch, which the README links to.

## Animation rule

An element's normal style is its final state. Keyframes animate from the hidden state with `fill-mode: both`. So when a viewer has reduced motion turned on (animations off), every SVG still shows all of its content.
